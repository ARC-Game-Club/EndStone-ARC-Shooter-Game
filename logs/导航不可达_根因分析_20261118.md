# 导航"不可达"根因分析（2026-11-18）

> 起因：服主问"怎么经常不可达了，是不是多样性寻路有问题啊"。
> 结论：**不是多样性寻路的问题**，是**烘焙导航图本身大面积断开**。

## 一、结论

**路径多样性（抖动 + 拥堵热度，枪战插件 0.4.56）不是原因。**
烘焙图里本来就有大片区域互相走不通，多样性只改边代价，改不了连通性。

## 二、三条独立证据

### 1. 时间线：失败早于多样性上线

| 日志 | "不可达"条数 |
|---|---|
| 2026-11-03-*（最早 11-03-27） | 27 |
| 2026-11-05-1 | 1189 |
| 2026-11-07-2 | 1308 |
| 2026-11-12-2 | 943 |
| 2026-11-17-1 | 384 |
| 2026-11-18-3 | 52 |
| latest.log（11-18 11:52 重启后，新多样性代码在跑） | 204 |

全部历史日志累计 **15656 条**，最早来自 **11-03**；而路径多样性是 **11-18**
才随 0.4.56 上线的。上线前后失败量同量级。

### 2. 对照实验：关掉多样性，一样失败

用服务器上真实的烘焙图（`plugins/arc_shooter_game/nav/*.nav.json`）+
日志里真实的起终点（3573 个去重对）跑对照：

| 场景 | 原始 A*（无钩子） | 加抖动（10 次/对） |
|---|---|---|
| 跨分量样本（前 60 对） | **60/60 失败** | — |
| 同分量样本（前 60 对） | **60/60 失败** | **600/600 失败** |

多样性只改边代价倍率（`cost_scale`）和节点罚金（`node_penalty`），
**连通性完全不变** → 结论一致。

### 3. A* 超预算：不可能发生

- `astar(..., max_expansions=200_000)`，超预算与真不可达**以前共用一句文案**。
- `closed[]` 保证每个节点最多展开一次 → **展开数 ≤ 图的节点数**。
- 实测：harbor **3586** 节点、炼狱小镇 **47467** 节点，都离 20 万差两个数量级。
- 真实数据重跑：**3573 个失败对里 0 个是 budget**。

## 三、真因：图断成好几块

| 图 | 节点 | 连通分量 | 最大分量 | 孤岛节点 |
|---|---|---|---|---|
| harbor | 3586 | 26 | 3055（85.2%） | **531（14.8%）** |
| 炼狱小镇 | 47467 | 258 | 37205（78.4%） | **10262（21.6%）** |

失败对分类（真实数据）：**跨分量 2674（74.8%）+ 单向边 899（25.2%）**。

- **跨分量** = 两块区域之间根本没有连起来的路。
- **单向边** = 弱连通但边是有向的（跳崖/单向通道），这个方向走不通。
  例：harbor `(-996,76,975)`（barrier 平台）↔ `(-1013,64,976)`（地面），
  中间落差 12 格 > `MAX_DOWN=5`，图里两个方向都没边。

**96 个出生点全部落在主分量** → 不是"一出生就卡孤岛"，是打起来后有人
站进了孤岛区域，另一个人够不到。

**烘焙数据没过期**：11-03 20:28 烘焙，晚于最后一次地形导出（15:17）。

## 五、已做的修复（枪战插件 0.4.58）

- `astar()` 加 `stats` out 参数，回填 `reason`（ok / budget / unreachable）
  和 `expansions`——"超预算"和"真不可达"以前共用一句文案，把排查带偏过。
- `navmap.query()` 失败分三类并带分量编号：
  - `component_split`：分属不同连通分量（起点 #3，目标 #50）
  - `oneway`：同在分量 #3，但这条路单向（跳崖/单向通道）
  - `budget`：A* 展开超预算
  同时回传结构化字段（`reason` / `start_component` / `goal_component` /
  `start_node` / `goal_node` / `expansions`）。
- `api_nav_status` 加 `nodes` / `components` / `island_nodes` /
  `island_pct` / `top_components`，不用翻 nav.json 就知道图断成几块。

**改完地图后**：`/gs bake <地图>` 重新导出并重烘，`/gs nav <地图>` 看
出生点连通性和孤岛统计。

## 六、还在定的：假人碰到"够不着的敌人"怎么办

假人在枪战模式是"只跟烘焙导航走"，路径失败 → 不回 `nav_active` →
扇形搜索兜底被 `navOnlyMode` 挡住 → **站桩不动**，只开火。
实测每局开局 6 分钟内有 5 个 bot 处于这个状态（fanchuan 54 次、
HipFireKing 53、BuckshotBob 53、PanFryKing 48、SleepyMuzzle 48）。

候选方案（服主 2026-11-18 待定）：

1. **换目标**——把这个敌人拉黑几秒，改追/打下一个能到的。
2. **退回引擎导航兜底**——朝敌人方向自己走（可能自己跳崖摔回地面）。
3. **保持现状**——站桩只开火。
