# 导航"不可达"根因分析（2026-11-18）

> 起因：服主问"怎么经常不可达了，是不是多样性寻路有问题啊"，随后又问
> "这个炼狱小镇地图你可以自己读取了去看看啊，怎么会走不通呢"。
>
> **最终结论**：
> 1. **不是路径多样性的问题**（抖动/拥堵热度只改边代价，改不了连通性）。
> 2. **不是地图断了**——地图是走得通的，走下 6~8 格的坎就到。
> 3. **是连通性规则把落差 >5 格整个禁掉了**，而这条规格来自**hard 难度
>    生存服**（"5 格内落地没伤害"），枪战服是 **peaceful 难度、摔落不掉血**，
>    用它当连通性判据纯属过度保守 → 大片区域被切成"孤岛" → AI 站着不动。

## 一、证据链

### 1. 时间线：失败早于多样性上线

| 日志 | "不可达"条数 |
|---|---|
| 2026-11-03-*（最早 11-03-27） | 27 |
| 2026-11-05-1 | 1189 |
| 2026-11-07-2 | 1308 |
| 2026-11-12-2 | 943 |
| 2026-11-17-1 | 384 |
| latest.log（11-18 11:52 重启后，新多样性代码在跑） | 204 |

全部历史日志累计 **15656 条**，最早来自 **11-03**；而路径多样性是 **11-18**
才随 0.4.56 上线的。上线前后失败量同量级。

### 2. 对照实验：关掉多样性，一样失败

用服务器上真实的烘焙图 + 日志里真实的起终点（3573 个去重对）：

| 场景 | 原始 A*（无钩子） | 加抖动（10 次/对） |
|---|---|---|
| 跨分量样本（前 60 对） | **60/60 失败** | — |
| 同分量样本（前 60 对） | **60/60 失败** | **600/600 失败** |

多样性只改边代价倍率（`cost_scale`）和节点罚金（`node_penalty`），
**连通性完全不变**。

### 3. A\* 超预算：不可能发生

`astar(..., max_expansions=200_000)`，`closed[]` 保证每个节点最多展开一次
→ 展开数 ≤ 节点数。实测 harbor **3586**、炼狱小镇 **47467** 节点，离 20 万
差两个数量级。真实数据重跑：**3573 个失败对里 0 个是 budget**。

### 4. 地形数据是完整的（不是导出缺失）

- 炼狱小镇导出 `unloaded_columns=0`、coverage **100%**；
  缺的 10579 列全是地图四周的空边界列（x 906~913 / 1090+ 整列无方块）。
- 区域 #50（x1057~1076, z933~966）：**680/680 列都有地形**，8054 个方块，
  1519 个站立点 —— **烘焙图节点 1519，与地形真实站立点完全一致**
  （地形有图里没有 = 0，图里有地形没有 = 0），且**没有一个出度 0 的死点**。

### 5. 接缝实测：它们就贴在主区旁边

#50 的 **323 个节点与主分量的水平距离全部为 0（同一列 x,z）**，
只差高度：

```
(1067, 73.0, 933) [#50]  ↔  (1067, 75.5, 933) [主分量]   同列，差 2.5 格
(1067, 73.0, 933) [#50]  →  (1067, 62.0, 934) [主分量]   同列，落差 11 格
```

接缝（平面 8 邻接、分量不同）共 7358 对，被拒原因分布：

| 原因 | main→#50 | #50→main |
|---|---|---|
| `up>1`（爬不上去 2.5~3 格） | 938 | 2741 |
| `down>5`（落差 6~8 格被禁） | 2383 | 932 |
| `clearance`（下落净空被挡） | 358 | 6 |

**`down>5` 那一类就是真相**：现实里走下 6~8 格的坎就到了，
但规则说"落差 >5 格不走"。

### 6. 垂直剖面（x=1067, z=933）

```
y=75  brick_slab        ← 支撑面 75.5   （主区上层地板，半砖）
y=74  .
y=73  .
y=72  mushroom_stem    ← 支撑面 73.0   （#50 的台面）
y=71  mushroom_stem    ← 支撑面 72.0
...
y=59  stone             ← 支撑面 60.0
```

73.0 的台面和 75.5 的地板之间是 2.5 格的坎（**爬不上去，游戏里也爬不上去**），
但同一片区域的另一头有 6~8 格的下落通道。**地图本身是通的。**

### 7. 难度对照：这条规则本来就不该用在这台服

| 服务器 | difficulty | 摔落伤害 | 落差规则该不该限 5 格 |
|---|---|---|---|
| MCBEShooterGameServer（枪战） | **peaceful** | **无** | **不该限** |
| MCBEAnarchyServer（生存） | hard | 有 | 该限（假人插件另有 max_drop=3） |
| MCBECreatorServer（创造） | peaceful | 无 | 不限 |

## 二、修复（枪战插件 0.4.59）

**落差上限改成可配置**（`settings.yml`）：

- `NAV_MAX_UP`（默认 1）—— 向上最多跳几格。**保持 1**：2.5 格坎游戏里
  也爬不上去，放宽只会造出不存在的路。
- `NAV_MAX_DOWN`（默认 **10**）—— 向下最多摔几格。原来写死 5。

**规则变了自动重烘**：烘焙产物 `nav/<map>.nav.json` 里记着当时的
`rule`，与当前设置对不上就当缓存作废重烘一遍（不然"改了设置没反应"）。

### 效果（重建整张图实测）

| 图 | 规则 | 分量数 | 最大分量 | 孤岛节点 |
|---|---|---|---|---|
| harbor | MAX_DOWN=5（旧） | 26 | 3055（85.2%） | 531（14.8%） |
| harbor | **MAX_DOWN=10** | **10** | **3487（97.2%）** | **99（2.8%）** |
| 炼狱小镇 | MAX_DOWN=5（旧） | 258 | 37205（78.4%） | 10262（21.6%） |
| 炼狱小镇 | **MAX_DOWN=10** | **152** | **42348（89.2%）** | **5119（10.8%）** |

阈值曲线（炼狱小镇）：5→258 分量 / 8→179 / 10→152 / 12→132 / 16→90；
harbor：5→26 / 8→12 / **10→10（拐点）** / 16→9。
默认取 10：harbor 基本接平，炼狱小镇接回一半以上，剩下的多是
**云杉/白桦树冠**（`#10`/`#20`/`#183`，共 726 节点）——那些本来就该是孤岛。

> 剩下的孤岛绝大多数是树冠（`spruce_leaves` / `dark_oak_leaves`），
> 本来就走不上去，不用管。

## 四、日志文案（0.4.58 已修）

以前一律报 `不可达（分量断开或只有单向跳崖边）`，把三种病混成一句，
排查时被带偏过。现在 `astar()` 回填 `reason`（ok / budget / unreachable），
`navmap.query()` 分三类并带分量编号：

- `component_split`：分属不同连通分量（起点 #3，目标 #50）
- `oneway`：同在分量 #3，但这条路单向（跳崖/单向通道）
- `budget`：A* 展开超预算

同时回传结构化字段（`reason` / `start_component` / `goal_component` /
`start_node` / `goal_node` / `expansions`），`api_nav_status` 加
`island_nodes` / `island_pct` / `top_components`。

## 五、还开着的一件事：假人碰到"够不着的敌人"怎么办

落差放宽后，孤岛从 21.6% 降到 10.8%（剩余多为树冠），但仍有零星情况
够不着。假人在枪战模式是"只跟烘焙导航走"，路径失败 → 不回 `nav_active`
→ 扇形搜索兜底被 `navOnlyMode` 挡住 → **站桩不动**（只开火）。

候选方案（服主 2026-11-18 待定）：

1. **换目标**——把这个敌人拉黑几秒，改追/打下一个能到的。
2. **退回引擎导航兜底**——朝敌人方向自己走（可能自己跳崖摔回地面）。
3. **保持现状**——站桩只开火。
